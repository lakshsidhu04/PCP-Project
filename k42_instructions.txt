EXTRA TESTS (use ONLY IF NECESSARY)
Test A: The "Spaced Out" Physical Core Test
We force Windows to put the 8 threads on 8 completely distinct physical cores (Cores 0, 2, 4, 6, 8, 10, 12, 14). They will not share L1/L2 caches; they only share the massive L3 cache.
Run this command:

start /b /affinity 5555 benchmark_k42.exe 8
Note Ops/Sec

expected:
Testing K42 Lock with 8 threads...
Expected Counter: 8000000
Actual Counter:   8000000
[SUCCESS] Lock is mathematically correct
Time Elapsed:     0.650107 seconds
Throughput:       12.3057 Million Ops/Sec


Test B: The Hyper-Threading Test
We force Windows to cram all 8 threads onto just 4 physical cores by using their logical hyper-threaded twins (Cores 0, 1, 2, 3, 4, 5, 6, 7). They will aggressively fight over and overwrite each other's tiny L1 caches.
Run this command:

start /b /affinity FF benchmark_k42.exe 8
